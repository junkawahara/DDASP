## 高

1. [ ] 【高】 `#external` 宣言された原子がルールでも定義されていると、clingo より多い答集合を出す
   - 再現: `#external e. {a}. e :- a. #show a/0. #show e/0.` → clingo は `{}`, `{a e}` の 2 個
     (`symbolic_atoms` で `e` の `is_external` は False: ルールで定義された時点で外部原子ではなくなる)。
     ddasp(`--all-atoms`, 両手法)は `{}`, `{e}`, `{a e}` の 3 個。gringo は `5 2 2` を出力し続けるため、
     `src/compiler.cpp:672-673` `is_external_` が立ち、`build_supported`(`:763`)で支持条件が省かれ、
     `build_unfounded`(`:849-852`)でも `~u` が強制される。つまり「ルールで定義された外部原子」も
     選択ルール `{e}` 扱いになる。
   - gringo が集約を書き換えるときに外部原子を補助的な選言の頭部に置く場合にも同じ差が出る
     (例: `#external e. { d }. g :- #sum{ -2,e0 : e; -3,g1 : g; 2,d2 : d } >= 0.` → clingo はどの割り当てでも
     UNSAT、ddasp は `{e}`)。ランダムテストでは通常プログラム 10,000 個中 17 個がこれに該当した。
   - README(「kept as free variables」)/`docs/DESIGN.md:39-40` はこのケースを扱っていない。
     `python/tests/conftest.py:42-78` の比較ハーネス(外部原子の全割り当てを列挙する)でも一致しないため、
     こうしたプログラムをテストに加えると失敗する。

2. [ ] 【高】 読み込んだ保存 DD の原子を本体にしか書いていないのに「defined by a rule」で拒否される
   - gringo は再帰的な集約(頭部原子、またはそれに依存する原子が集約内に現れる)で `!=` や負の重みを使うと、
     補助原子との選言ルール `aux | a :- not aux2` を生成し、本体にしか書いていない原子 `a` が頭部に現れる。
     `src/compiler.cpp:1021-1024` はこれを「プログラムが定義している」とみなして例外を投げる。
   - 最小再現: P1 `{ a }. #show a/0.` を `--save`、P2 `j :- #count{ a : a; j : not j } != 1.` を `--load`
     → `ddasp: error: loaded DD: atom 'a' is defined by a rule of the program; loaded atoms may only occur in bodies`。
     Python `compile_text(..., dds=[...])` も同じ `ValueError`。clingo で P1+P2 を解くと `{}` の 1 個。
     `#external a. #show a : a.` を付けた P2 の aspif には `1 0 2 5 1 0 1 -6`(頭部 `{__atom5, a}`)が含まれる。
   - `j :- #sum{ 1,a : a; 1,j : j } != 1.` も同様。`=`, `>=`, `<=` や非再帰の集約は問題ない。
     ランダムテストでは保存 DD 9,500 件中 179 件(集約に `!=` か負の重みがある再帰的なもの全部)がこれで失敗した。
     同じ書き換えを通常の `#external a.` に対して行った場合は ddasp は正しく処理するので
     (`#external a. j :- #count{ a : a; j : not j } != 1.` は `{}`, `{j}`)、判定だけが厳しすぎる。
     README / GUIDE 9 章 / DESIGN は「本体と制約にだけ使える」と書いているが、この制限は満たしているのに拒否される。
